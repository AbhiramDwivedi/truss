# Goal: truss 0.31.0, speed

Client ruling, 2026-11-13: "the first and foremost thing i need is speed. its painfully slow right now." This run
fixes speed only; everything else is in [0.32.0.md](0.32.0.md). Base: main at 0.30.0 (220e1d5e) or later.

Rules for every item: each behaviour change has a failing-first test; cross-platform (Linux, macOS, Windows); crews
own their docs; tests are targeted, full suite only when reach is unclear and at release; never route around a gate.
The PM decides evidence-obvious calls itself and logs them; it escalates only real product, risk or money calls.

## Evidence (wave 4, 6 crews, 4-core host, 2026-11-12/13)
- ~1.5 days from plan to release; 20 crew stops; 2 of 6 crews never reached a pipeline PASS and were hand-merged.
  The wave-4 PM's verdict: "not better than the baseline" (wave 3).
- Full `npm test` 12-26 min, 2-3 at once (host load up to ~20 on 4 cores). Green, every fix round and every QC round
  ran it (one QC acceptance re-run alone 13m45s; QC's own run overruns the 600 s Bash limit). Green failures under
  load were the most common stop (a timing test ran 41 ms over its limit).
- heavySlots 2 on 4 cores; the slot wait (540 s) is shorter than one suite run, so crews stopped BLOCKED waiting.
- Merge conflicts on shared docs (docs/features.md, docs/knowledge/, architecture.md, .claude/rules/plugin-tests.md)
  on almost every merge, ~2 h QC round each. bin/factory.ts (4,382 lines) is touched by 91 of 573 commits in 14
  days, workflows/stage.js (2,549 lines) by 58: nearly every crew owns one of them.
- Line citations into churning files stopped crews on owns-check.
- A PM ruling at QC was never built on resume, wasting a QC round three times and blocking one crew (item 6).
- A client-only gate (session-audit waiver) on two transcripts from an API outage held every merge for hours.

## Step 0: baseline (before any change)
A script measures, per wave-4 crew, total wall-clock and its split: test runs, slot waits, QC rounds, conflict
resumes, agent work, waits on the client, idle gaps. Sources: the wave-4 run dir if it is on this machine, else the
numbers above. Write the result to the run's report. Rank the items below by measured cost; if the data shows a bigger
cost not listed, add it (the list is a starting point, not the scope). Note: the retro's timing script timed out after
90 s over the wave-4 transcripts; make the baseline script fast enough to finish.

## Items (quickest win first)
1. **Targeted testing by default.** A script (no agent judgement) maps a diff to the tests that cover it: test files
   that import a changed file, transitively, plus the crew's acceptance and regression tests, plus whole-repo checks
   triggered by their own inputs (e.g. the citation check when a doc or cited file changes). Green, fix and QC rounds
   run that set. Full suite when reach is unclear (config, shared test helpers, harness, package.json, an unimported
   file, a diff over a threshold) and at merge to main / release. QC never re-runs a suite already green on the same
   head; it reads green's result. Acceptance scripts stop ending in a blanket `npm test`. A schema-declared
   `.claude/truss.json` key maps paths to test commands for non-JS stacks; init proposes it. Log the selected set and
   why. No test run may overrun the Bash tool's 600 s limit in the foreground: long runs go to the background.
2. **Heavy slot fit for purpose.** heavySlots for this repo back to the host default (1 on 4 cores). The wait scales
   with the measured suite time, not a fixed 540 s. Targeted runs don't take the slot. The slot is released when the
   suite ends, not held through finish. Never more suites at once than heavySlots allows (wave 4 saw more).
3. **No stops on obvious calls.** Grade every gate by risk. Dangerous actions (production, money, secrets,
   force-push, deleting delivered work) stay hard stops; the rest decide automatically or by the PM, with a logged
   evidence line, auditable after. First cases: the session audit ignores no-work/outage (`<synthetic>`) transcripts
   and transcripts still in progress (another workflow's live agent), and the PM may waive an audit hit itself.
   Audit every client-only gate the same way. The program-manager and project-manager prompts say, in these words,
   that the role is **brave**, **empowered** and **accountable** (client ruling 2026-11-13; a test pins all three
   words in both); gates stay gates.
4. **Shared docs stop conflicting.** Each crew writes its own fragment (e.g. docs/features.d/<crew>.md, architecture,
   knowledge and rules fragments); a deterministic step stitches them at merge or release. Frontmatter-only conflicts
   resolve automatically. Docs cite code by symbol, never by line (lint enforces it), so churn can't stale or trap a
   citation.
5. **Refactor `bin/factory.ts`** into one module per command group, with factory.ts a thin dispatcher, and
   **`workflows/stage.js`** into step modules (bundled by a cross-platform build step if a Workflow script must be
   one file, with a test that the committed bundle matches its sources). No behaviour change; the suite is the
   contract. Goal: two crews rarely share a file. Smaller import graphs also make targeted tests sharper.
6. **A PM ruling at QC is built on resume.** Today an answers resume whose saved tasks are all done runs no member
   (stage.js, the resume path before `green`): it goes green, knowledge, gates, scope, QC, and the ruling's ordered
   changes reach no builder; a fix happens only after the next QC FAILs (`fixFindings`). Fix: an answers resume
   whose ruling orders edits or cherry-picks spawns a fix builder before green, and its commits are verified in the
   head QC sees. Also: a member's commit was dropped unmerged after a PROPOSAL stop; members' commits must all reach
   the crew branch or the stop names the dropped ones. Failing-first test on the stubbed crew.
7. **Other time-costing bugs from wave 4:**
   - QC passed an out-of-owns edit that owns-check refused later: QC runs owns-check's rule, saving a round.
   - `tests/lifecycle-029` pins the release title "0.29.0", so it breaks every release: pin a version-free form.
   - `inbox.check.ts` timing test flakes under load (11 s budget for a fixed 10 s wait): raise to 12 s and the child
     timeout to 15 s, or remove the wall-clock dependence.
   - `goalCheck` has no timeout.
