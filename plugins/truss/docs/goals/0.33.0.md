# Goal: truss 0.33.0, speed II: test selection, runner cost, resume and flake rounds

Client pick, 2026-11-14, from the six goals report-0.32.0.md proposed: the three speed goals. Base: main at 0.32.0
(b76b04d5) or later. The other three proposals (planner owns and ordering, mid-run scope gate, small items) and the
cost goal are not in this release.

**How it runs:** through truss itself (/truss:run) on the 0.32.0 build, on the Mac, handed off through the U drive as
0.32.0 was (release-0.33.0.bundle, report-0.33.0.md, READY-0.33.0 last; BLOCKED.md when stuck). Truss bugs the run
hits are fixed in the plugin with a failing-first test and listed in the report, never routed around.

Rules for every item: each behaviour change has a failing-first test; cross-platform (Linux, macOS, Windows); crews
own their docs; targeted tests, full suite only when reach is unclear and at release; never route around a gate. The
PM decides evidence-obvious calls itself and logs them; it escalates only real product, risk or money calls.

## Evidence (0.32.0 run, report-0.32.0.md)
- Test runs are still the largest bucket: 17h17 of 54h02 crew time. A "targeted" run selects 84-86 files and costs
  9-14 min, close to the full suite (~8 min on the Mac).
- R-139 missed: a one-line change to a leaf of the old hubs selects 135-145 of 214 test files (bar: 50), because most
  tests spawn the whole factory CLI and every CLI run calls `parseFlags`, `withLock` and `CliError`.
- Bug L: a knowledge-only answers resume replayed the whole crew tail: 87 min, 39 agents, about 70 min of suite runs,
  where a sync, one green and the lint (about 5 agents, 15 min) were needed.
- Bug N: one known flake (heavy-031) in the full suite cost a full fix round, about 45 min.
- Runner cost: about 85K tokens per runner spawn to relay one factory command; every 540 s poll of a pending heavy
  job spawns a fresh runner (F-19, F-38). Bug L's run spawned 32 runners.

## Items
1. **Test selection that is actually targeted** (bug M, F-46, F-13, F-50, R-139's follow-ups).
   - Select from the diff since the last green head on this crew branch plus the files the target merge brought in,
     not target...HEAD. A docs-only commit selects only the checks whose inputs it changed.
   - Per-command loading in `bin/factory.ts`, so a command loads only the modules it uses.
   - Fewer tests that spawn the whole factory CLI: test logic directly where the CLI is incidental; keep a small set
     of CLI end-to-end tests per command.
   - A stage test map, so a change to one `workflows-src/stage` module selects that step's tests (`loadStageStep`).
   - Bar: R-139 (a one-line change to a leaf of the old hubs selects at most 50 test files) met, or the report shows
     why not with counts. Correctness first: a selector that misses a test that would fail is worse than a slow one;
     prove it on the 0.32.0 run's real diffs (every test that failed there is still selected).
2. **Runner and heavy-job collection** (F-19, F-38). A factory command the stage needs is run without a fresh agent
   per call where the Workflow can do it; a pending heavy job is collected by one waiter, not a new runner every
   540 s poll. Measure runner spawns and tokens per crew before and after.
3. **Resume only what is needed** (bug L, bug O). An answers resume whose answers are all at `knowledge` or later,
   with every task done, skips green, checkpoint and stress before the knowledge step; a head refused only by the lint
   gets a resume that reruns the lint (and the green check on the synced head when the sync moved it), not gates,
   green and QC. Bug O: `knowledge-commit --sha` handles a merge commit.
4. **A flake costs a re-run, not a fix round** (bug N). When the full suite fails, re-run only the failing test files
   once on the same head before charging a fix round; a pass on re-run is logged as a flake with the test's name and
   reported in the retro, never silently dropped. A test that flakes twice in a run is a finding for the crew that
   owns it.
