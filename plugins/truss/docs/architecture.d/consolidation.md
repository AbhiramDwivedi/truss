### Factory modules (0.31.0)

`bin/factory.ts` is only the dispatcher: argument parsing, `main`, the command table (`CORE_COMMANDS`, `PLUGIN_COMMANDS`), the `--status` and `--reap-first` flags, and re-exports of every name it exported before, so existing imports keep working. Each command group lives in its own module under `bin/factory/`, so two crews rarely change the same file. `shared.ts` holds the helpers the modules share, such as flag parsing, the plan file, settings, events, `PLUGIN` and `FACTORY`. `runs.ts` reads Workflow runs and QC reports. `retro-mods.ts` is the lazy load of `retro/` and imports no sibling. The command modules are `plan.ts`, `check.ts`, `doctor.ts`, `crew.ts`, `start.ts`, `warnings.ts`, `personas.ts`, `resources.ts`, `heavy.ts`, `gates.ts`, `finish.ts`, `audit.ts`, `retire.ts`, `decide.ts`, `decisions.ts`, `knowledge-cmds.ts` and `consolidate.ts`; each one's header comment says what it owns. No module imports `factory.ts`, whose top-level `await` would make an import cycle. `gates.ts` needs `main`, so it exports `gatesRun(argv, main)` and `factory.ts` binds it as `gatesMain`. `heavy.ts` and `gates.ts` run the CLI again through `FACTORY`. `factory-split-031.check.ts` pins this layout.

### Memory consolidation (0.32.0)

`factory consolidate --repo R --dir D` (`cmdConsolidate` in `bin/factory/consolidate.ts`) proposes one diff that tidies the knowledge docs between waves. It reads three kinds of doc: the feature map, every markdown file under the knowledge dir (a `.d/` fragments dir excluded) and the architecture doc. It decides in code, never through an agent, by four rules. `mergeDuplicates` merges a second entry with the same capability heading (compared without case, emphasis or trailing punctuation) into the first; it applies to the feature map only. `pruneUnsupported` replaces an entry with a one-line comment that names the entry and the reason when none of its entry paths (`featurePaths` in `bin/knowledge.ts`) exists any more. `repointLines` replaces a line citation to a code file with the file and its enclosing top-level symbol (`enclosingSymbol`); a line that falls between declarations is left alone. `flagMissing` adds a `> consolidate:` line under a claim whose cited symbol the cited file no longer declares (`declares`), and never rewrites the claim, because only a reviewer can say whether the code or the doc is wrong.

The command writes `D/consolidation.patch`, a unified diff that `git apply` reads (`unifiedDiff`), and `D/consolidation.json`, which holds the head, the files and one `{kind, doc, reason}` row per change with `kind` one of `merge`, `flag`, `prune` and `repoint`. It changes no tracked file. `--accept` refuses while a doc in the patch has uncommitted changes, checks the patch with `git apply --check`, applies it and commits once as `docs: consolidate knowledge`. `--reject` removes the proposal. Nothing is deleted or applied without `--accept`. The run skill runs it when a stage's last crew has merged and before the next stage starts, and a read-only `truss:checking-engineer` reviews the diff. `consolidation-032.check.ts` pins this behaviour.
