### Workflow calls (ADR-0009)

A Workflow script's `agent()` is not an Agent tool call, so none of the Agent gates above runs for it: the probe's checking engineer with no model ran on the session model, and a project manager started past the cap ([ADR-0009](adr/0009-workflow-factory.md), Probe). ADR-0009, Decision 6, added three things to `hooks/register.ts` and changed nothing else in it:

- `export` on the existing `fencedBlock` (`register.ts`), so `factory.ts plan-write` applies the plan-file route's block rules.
- Two pure exported functions. `workflowRoleVerdict(roles)` refuses a roles table that isn't an object, a role key that doesn't match `^[a-z]+$`, a `project-manager`, `commissioning` or `integrator` key or a role whose `agentType` is `truss:project-manager`, `truss:commissioning-engineer` or `truss:integrator`, a role that isn't an object, a model other than `opus` or `sonnet`, and an effort other than `low` or `medium` (`register.ts` `workflowRoleVerdict`). `workflowCallVerdict(plan, input)` (`register.ts` `workflowCallVerdict`) returns undefined for no plan or a plan below v2. Otherwise it refuses a call that gives both `script` and `scriptPath`, and calls a script Truss's when its `scriptPath` is `<pluginDir>/workflows/plan.js` or `stage.js`, or its text equals one of those files byte for byte. A script that isn't Truss's is refused with "Truss agents run in a Workflow only from the plugin's plan.js and stage.js" when its `scriptPath` can't be read or its text contains `truss:`; any other such script gets undefined. A Truss script is refused with no `args.truss` object; then `workflowRoleVerdict(args.truss.roles)` applies; then it is refused when it matches both scripts, when `plan.js` doesn't run with `kind: "plan"` or `stage.js` with `kind: "stage"`, when `kind: "plan"` meets a plan whose `approvedAt` is set, or when `kind` is neither. A `stage` call is refused without `args.truss.crews` as a list, and for any crew with no slug, whose `status` isn't `running`, or that `planVerdict` refuses. Every refusal starts `[truss] Refused:`.
- One handler, `on('tool.call', { tool: 'Workflow' }, ...)`, right after the Agent handler, for main-session calls only (`e.agentId === undefined`): it reads the plan within `PLAN_READ_MS`, returns the verdict's deny or calls `next(e)`, and logs each refusal with `logRule`.
- The `trussFile` seam ([ADR-0024](adr/0024-factory-fixes3.md), item 29, proposed; goal `factory-fixes3`'s stage 1 builds it). When `start --args-file P` resolves inside the truss dir, its short output gains `workflowArgs: {"trussFile": P}`, and the PM passes that as the Workflow's `args`. For a plugin script, the handler's `expandTrussFile(args, trussDir, read)` reads P, takes its `truss` object, and refuses both keys at once, a path that isn't absolute or leaves the truss dir, and a file that isn't JSON or holds no object `truss`. `workflowCallVerdict` then checks the expanded object, and the handler calls `next` with `args: {truss}`. Without `trussFile` the handler is unchanged. `stage.js`, run without an object `args.truss`, throws at once with a message that names `args.trussFile`, so a runtime that ignores the rewritten args stops before any agent runs and the PM passes `args.truss` inline.
- The `livePage` seam ([ADR-0025](adr/0025-factory-fixes4.md), item 40, proposed; goal `factory-fixes4`'s stage 1 builds it): `factory.ts` `crewEntry` → `workflows-src/stage/ux.js` `uxReviewPrompt`, which reads it as optional. Every `start` form sets `entry.livePage` to the first line of the goal file's `## UX` section that starts with `Live page`, after an optional `- ` or `* ` bullet, trimmed and given whole; it is `null` when there is no such line or no `## UX` section.

The three crew-keyed Agent gates, `agentVerdict`, `effortVerdict` and the rework-allowance gate, key on `crewOf(callerId)` and can't fire for a workflow agent, which has no `truss:project-manager` ancestor. On the Workflow path the script's `spawn()` (throws on a role without model or allowed effort), `workflowRoleVerdict` in `start`, `plan-args` and this gate, `stage.js`'s spend count and `finish`'s transcript audit and `qcFails` check replace them: those rules are the script's, the CLI's and the audit's, not a hook's refusal (ADR-0009, Decision 4, "What replaces the project manager's gates"). `finish` also audits every Workflow run of the session since the newest `## Run` header that is Truss's or holds a `truss:*` agent, and while any entry stands it merges nothing (Decision 1, "finish, session audit"). It passes over no-work and in-progress transcripts, and the program manager waives a standing entry on evidence ("Gate grades (0.31.0)" below).

Workflow refuses a `scriptPath` inside the plugin cache, so `plan-args` and `start` copy the script byte for byte as `truss-plan.js` or `truss-stage.js` into a scripts dir and print the copy's path (`scriptPathFor`, `bin/factory/shared.ts`). The dir is `--scripts-dir` when given, else the session scripts dir: `sessionScriptsDir` takes the path segment directly under `<git common dir>/truss/` of the truss dir as the session id, finds that session's main transcript with `transcriptsOf`, and returns `<dir of the transcript>/<session id>/workflows/scripts` (`sessionScriptsDir`, `bin/factory/shared.ts`). When the truss dir is not under `<git common dir>/truss/` or no transcript is found, `scriptPath` is the plugin's own file, as before. The gate still recognises the copy by its text, and an inline `script` with the same text too (Decision 6, "scriptPath fallback").

`workflows/stage.js` is generated (0.31.0, speed goal item 5). Its source is the step modules in `workflows-src/stage/`: `args`, `texts`, `globs`, `schemas`, `spawn`, `crew`, `runner`, `gates`, `answers`, `check`, `prompts`, `members`, `calls`, `replies`, `integrate`, `tasks`, `ruling`, `fixes`, `split`, `green`, `stress`, `scope`, `qc-context`, `knowledge`, `lint`, `qc`, `ux` and `chain`. The script must stay one file, because `start` copies it byte for byte, the gate knows it by its text, and a Workflow script may hold no import. So the modules are plain script parts, not ES modules, and they share one top-level scope as the single file did. They sit outside `workflows/` because `plugin.json` declares no workflows, so Claude Code might scan that folder, and a part has no `meta` export. `bin/build-stage.ts` (`npm run build:stage`) drops each module's first line, a `// stage.js module:` comment, and joins the rest in its `STAGE_MODULES` order under a one-line generated header. It uses Node built-ins only and writes `\n` line ends, so a build gives the same bytes on every platform. The module order is the old file's order, so the bundle is the pre-split file plus that header. The committed `stage.js` is what runs and what the tests exec. `tests/stage-bundle.check.ts` rebuilds into a temp dir and fails when the bytes differ, so a module edit without a rebuild fails the suite. `bin/testmap.ts` reads the header's "from the modules in ../workflows-src/stage/" and treats `stage.js` as using every module, so a change to one module selects every test that reads `stage.js`. A test that calls `loadStageBundle` reaches `stage.js` the same way, though the call names no path: `stageBundles` in `bin/testmap.ts` links any test-side file whose text holds that name to every generated `stage.js`.

Since 0.32.0 a stage test can drive one step without the bundle ([ADR-0050](adr/0050-stage-step-tests.md), R-140). `loadStageStep(file, stubs)` in `bin/build-stage.ts` reads one module under `STAGE_SRC_DIR`, drops its `// stage.js module:` line and its `export` keywords, and runs the rest as an AsyncFunction whose parameters are the stub names (`agent`, `args`, `log`, and runner-side calls such as `integrate`). It returns `{ loaded, scope }`, where `scope` holds the names the module declares at column 0. A free name that is neither declared nor stubbed throws a ReferenceError when the step reaches it. A file outside `STAGE_SRC_DIR`, or one without the module comment, is refused. `loadStageBundle(stubs)` loads the committed `stage.js` with the same stubs but cuts it before the top-level run line `const results = await Promise.all(F.crews.map(runCrew))`, and throws when that line is missing; when `stubs.args` has no `truss` it adds `{ dir: '/', repo: '/' }`, because the bundle's load-time code needs an `args.truss` object. A test that names one module by a relative literal (`'../workflows-src/stage/ruling.js'` in `tests/stage-step-ruling.check.ts`) is selected by a change to that module only. The older stage tests still load the bundle, so a one-file change to a stage module still selects 48 test files, and 49 for `ruling.js`.
