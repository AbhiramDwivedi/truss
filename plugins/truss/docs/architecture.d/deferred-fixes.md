## Deferred fixes (0.32.0)

The deferred-fixes crew closed the items that report-0.31.0.md listed under "Deferred or unverified", or gave each a reason line in `plugins/truss/tests/fixtures/deferred-031/ledger.json`. The code changes are four.

- **Run target.** `settingsOf` in `bin/factory/settings.ts` takes an optional truss dir. A `target` string in that dir's `plan.json` wins over `.claude/truss.json`. Every caller that knows a dir passes it: `settingsFor(f, repo)` reads `--dir` from the flags for `settings`, `land`, `finish`, `check`, `goal-check`, the knowledge gates and `gated-merge`, and `start`, `crew` and `approve` pass their own `dir`. Among the run skill's prompt callers, the plan-table `settings` command, the project manager path's `gated-merge --ff-only` and the scrub-then-merge `gated-merge` pass `--dir <truss dir>`. The all-solo path's `settings` and `gated-merge` do not, because that path writes no `plan.json` and so has no plan target. `plan-check` refuses a `target` that `validBranchName` rejects. ADR-0053 records the decision.
- **Scripts dir fallback.** `scriptPathAuto` in `bin/factory/roles.ts` tries the session scripts dir, then `<truss dir>/scripts`, then `<os.tmpdir()>/truss-scripts`, and falls back to the plugin's own script last. An explicit `--scripts-dir` is never retried.
- **Warnings from the named session.** The main session's `classic.SessionStart` hook in `hooks/register.ts` writes `<truss dir>/session-start.json` whole on the `startup`, `resume`, `clear` and `fork` sources, never on `compact`. `useSessionStart` in `bin/factory/warnings.ts` makes `sessionStartOnce` answer with that record's `ts` when `start` runs with that dir (`recordSessionStart`). Without a usable record it answers with the first timestamped record of the `--transcript` session's main transcript, and then with the `CLAUDE_PID` process start. `TRUSS_SESSION_START` still wins over all three. The transcript is only a fallback: a fresh session's first timestamped record can come later than the process start, and a resumed session's transcript starts before the process that reloaded the agents. The hook's `rootOf` cache is keyed by the session id, so after a `/clear` or a fork every handler names the new session's truss dir. ADR-0016 records the change as a dated amendment to "The session start", item 3.
- **Notify tree kill proof.** `bin/notify-run.ts` hands the notify command's stderr down when `TRUSS_TEST_NOTIFY_STDERR=inherit`, so `inbox.check.ts` holds the read end of a pipe that closes only when the whole tree has exited. The variable is a test seam; unset, stderr is ignored as before.
