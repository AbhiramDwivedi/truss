### Admission and reap folds in stage.js (R-142, 0.32.0)

A member start costs no separate admit or reap runner call where a factory call sits next to it. `redStep` sets `crew.admitPlan` (`planAdmit`) for the first member the crew will start, the UX direction when the crew has one to take, else the planner, and `runFactory` adds `--admit-first <slug> --admit-label <label> --admit-title <title>` (with `--admit-persona` and `--admit-high` for a member that has them) before `--dir`, and before heavy's `--`, on the red check. The answer's `admittedFirst` object waits in `crew.admitFirst`, and `admit` takes it (`takeAdmitFirst`, only for the same label, title, persona and high) instead of calling the runner; any other runner call voids it. A held `admittedFirst` is judged as a held admit is (`held by admission:`, `BLOCKED: budget:`, `BLOCKED: awaiting client:`). A crew with saved tasks, or a start no factory call precedes, keeps the standalone admit. The crew-end reap rides on the late-reply read in `runCrew` (`--reap-first`, as every member's reap does) and runs alone (`reap`) only when it is still due after that read, which is when no factory call follows.
