## Generic retro (0.32.0)

- What: the retro counts where a run's wall-clock and tokens went from structured files only, never a transcript, and works on a truss run dir and on a plain project dir with no `plan.json`. Each finding carries counted evidence (a `measures` key and its exact value), a cost (`wallMs`, `tokens`, `usd`), a fix and a target, and findings are ranked by wall-clock, then tokens, never by category. `CHECKLIST` (time, code structure, tests, quality loop, rules and gates, cost) is a starting list, never a filter: the judge may name a new category, and `parseFindings` and `parseTriage` keep it. A finding about product code becomes a proposed goal for the client and never enters the fix goal. USD appears only when the client's `pricing` config prices the model.
- Entry points: `plugins/truss/retro/counts.ts` (`problems`, `CHECKLIST`, re-exported); `plugins/truss/retro/problems.ts` (`problems`, `assemble`, `rankCmp`); `plugins/truss/retro/problems-code.ts` (`codePart`); `plugins/truss/retro/cli.ts` (the `problems` command, `parseFindings`, `parseTriage`); `plugins/truss/retro/evals/` (the recorded judge and triage output the rubric grades); `plugins/truss/agents/retro-judge.md`; tests `plugins/truss/tests/retro-generic-032.check.ts`, `plugins/truss/tests/retro-generic-live.e2e.ts` (opt-in, `TRUSS_RETRO_LIVE_EVAL=1`).
- Docs: `plugins/truss/docs/adr/0051-generic-retro.md` (amends ADR-0012); retro knowledge doc `docs/knowledge/retro.md` (code seams, fixtures, the `recur` extract leftover); [architecture](../plugins/truss/docs/architecture.md) ("The self-improving retro (ADR-0012)").
- Owner: `truss-plugin-node` for the code; the judge and triage prompts are unowned until a `truss-prompts` persona is installed.
