## The store (`bin/store.ts`)

- Since 0.32.0 ([ADR-0049](../../plugins/truss/docs/adr/0049-hub-split.md)) `bin/store.ts` is a barrel that only re-exports three leaves. `bin/lock.ts` is the only lock and atomic-write code. `bin/transcripts.ts` holds both transcript roots: `transcriptsOf` for spend and the queue's stale rule, `proofTranscriptRoot` for the inbox proof. `proofMain` in `bin/inbox.ts` walks the proof root itself. New modules import `CliError`, `usage`, `refuse`, `flat` and the other moved helpers from `./core.ts`, never from `./store.ts` or `factory.ts`.
- `withLock(dir, name, fn, {waitMs, platform, fs, host, now})` holds `<dir>/locks/<name>.lock/owner.json` with `{pid, host, token, since}` (lock.ts `withLock`). Only the owner's token releases it.
- A lock is stale when: the owner is a dead pid on the same host, or `since` is over `STALE_AGE_MS` (120 s) old, or there is no `owner.json` and the dir is over `OWNERLESS_MS` (3 s, inside `withLock`'s default 5 s wait) old (lock.ts `STALE_AGE_MS`, `OWNERLESS_MS`).
- Busy past `waitMs` (default 5000) throws `StoreBusy`: `CliError` code 2, body `{error: 'store busy: <name>'}` (lock.ts `StoreBusy`).
- Takeover never renames a lock aside: that would open a window where the path is free while a live owner is still running. One breaker at a time holds the mutex `<lock>.break`, re-reads `owner.json`, and removes the lock only if the token is still the one judged stale. An ownerless lock's age is re-checked under the mutex. A mutex over `OWNERLESS_MS` (3 s) old is cleared after an ino+mtime re-check (lock.ts `takeOver`). This deviates from contract-025 section 2 line 83.
- Lease (`takeLease`, `refreshLease`, `releaseLease` in `lock.ts`): `takeLease(dir, name, opts)` creates `<dir>/locks/<name>.lease` with `createExclusive` (`{pid, host, since, refreshed, token}`) and returns `{token}`, or `null` while a live lease holds. `refreshLease(dir, name, token, opts)` returns a boolean; `releaseLease` removes only its own lease. Stale: same-host dead pid (a live pid keeps its lease however old: `finish` blocks in spawnSync while the acceptance test runs), or, for another host's lease only, older than `LEASE_STALE_MS` (300000). A stale lease is removed under the `<name>.lease.break` mutex after a token re-check. On win32 a failed removal (EPERM, EACCES) returns `null`, and a later call recovers. `LEASE_REFRESH_MS` (30000) has no timer caller: `finish` refreshes only before each crew's merge. Used as `finisher-<slug>` (ADR-0048).
- `opts.fs` is `Partial<typeof node:fs>`; an omitted function falls back to the real one (lock.ts `FsLike`). `appendJsonl` takes the lock named by its second argument under the dir it is given; its file argument is relative to that dir.
- Orphan tmp files: `writeJsonAtomic`, `createExclusive` and `withLock` call `sweepTmp`, which removes `<name>.<pid>-<uuid>.tmp` files older than 120 s whose pid is dead, or older than 24 h whatever the pid. It runs at most once a minute per dir per process; a live writer's fresh tmp is never removed (lock.ts `tmpOf`, `sweepTmp`).
- The test title "a lock older than 200 s is taken over" stays as pinned by contract-025; the code threshold is 120 s. See `product-decisions.md`.

## Admission holds

`admission(dir, repo, plan, crew, command, running)` runs `holdOf()` before the memory checks (`admission` in `bin/factory/admit.ts`). `holdOf` calls `blockingFor` (answer `awaiting: true`), then, only when `cfg.budget` is an object, `budgetVerdict` (answer `budget: true` with scope, spentUsd, limitUsd, why; plus a `budget-hold` event and a budget escalate). An escalate error never lifts the hold; it goes into the hold's `escalateError` field. The budget escalate's `ref` is the verdict's own `v.ref` when it is a non-empty string, else `budget:<sid>:<scope>:<run|slug>`.

Plan writes: `savePlan` goes through `writeJsonAtomic`, and `patchPlan` (`bin/factory/plan-file.ts`) re-reads `plan.json` under the `plan` lock before it edits and saves. `approve`, `start`, `mark-merged`, the merge gate, `plan-write` and `owns-extend` all write the plan that way, so none drops another's edit. `plan-write` over an approved plan with no running or planned crew archives it as `plan-<approvedAt>.json/.md` (`keepExisting` in `cmdPlanWrite`); a running or planned crew (a run not finished) refuses it. `workflows-src/stage/check.js` `check()` runs `heavy` up to 3 times (`HEAVY_WAIT_ROUNDS`) before it stops `heavy slot busy`.

`workflows-src/stage/crew.js` `admit()` maps those answers to `Stop BLOCKED` with `BLOCKED: budget: <why>` or `BLOCKED: awaiting client: <why>`, and retries once, straight away, on exit 2 `store busy` (`admit` in `workflows-src/stage/crew.js`). There is no pause: scripts have no timers, and factory's own 5 s lock wait already ran. A budget or awaiting hold is never retried: `admit --wait-ms 90000` refuses it at once. Only a memory hold is re-checked inside factory, every 2 s first (`cmdAdmit`, `bin/factory/admit.ts`). `qc()` returns `longTermCosts` (lines starting, after optional bullet, number, quote or bold/code markup, with `LONG-TERM-COST:`; a none-word body is skipped; same regex as `LINE_RE` in `bin/guard.ts`) only when non-empty (`ltcLinesOf` and `qc` in `workflows-src/stage/qc.js`).

`start` output has no top-level `entries`: started full crews are in `truss.crews`, direct crews in `direct`, project manager crews in `projectManagers`, held ones in `held` with `why` (`stageOut` in `bin/factory/start.ts`).

## Cost meter (`bin/cost.ts`)

- `sweep(dir, repo?, {platform?, waitMs?})` returns `{rows, files, bad, found}` and runs under the `usage` lock (cost.ts `sweep`). `platform` is a parameter so tests cover win32.
- `D/usage-cursor.json` is `{files: {<path key>: {offset}}, project, ccEstimate: {usd, ts} | null}`; win32 keys are lowercased paths (cost.ts `sweep`). Dedupe uses the msgId set loaded from `D/usage.jsonl`, not the cursor, so a deleted cursor re-adds nothing (cost.ts `sweep`).
- Torn rows: `readJsonl` skips an unterminated last line and any line that doesn't parse (lock.ts `readJsonl`). Before appending, the sweep writes a newline when `endsTorn` finds the file's last byte is not one, so a new row is never glued to a torn one (cost.ts `sweep`).
- `factory cost` (`costOf`) and the inbox commands `escalate`, `resolve`, `mark-applied` and `list` take `--dir` through `absDirOf` (`bin/inbox.ts`): a relative `--dir` is a usage error, so `sessionOf` never sees a relative basename.
- Attribution (workflow label, spawn event, `worktreePath`, Agent label, `main`, unattributed) is computed on every read and never stored in rows.
- Raise refs: `budget:<sid>:crew:<slug>`, `:workType:<slug>`, `:run:run`, `:session:session` (cost.ts). `sessionUsd` is checked at every admit and at queue-next; a held session verdict carries `ref` `budget:<sid>:session:session`, which `holdOf` and `queue-next` escalate with, so one raise lifts every crew (`budgetVerdict` in cost.ts; ADR-0038 amendment 2026-11-11). Every `why` starts `budget: `.
- A busy usage lock is handled by `budgetVerdict` in two ways. With a `usage.jsonl` it reads that file as it stands and accepts the lag. With no `usage.jsonl` the spend is unknown, so it sweeps once more with the store's default wait and lets `StoreBusy` through (exit 2, never an admit; ADR-0038 amendment 2026-11-11). `factory start` wraps its admission in `heldOnBusy`, which holds that crew with `why` `store busy: usage` and still reports the crews already started in the call. `crewCost` gives `usd: null` on any busy lock (`sweepOrRead`, `crewCost` in cost.ts). `factory cost` reads through `sweepOrRead` too: on a busy lock it prints `sweep.busy: true`, and with no `usage.jsonl` and no cursor `run.usd` and `session.usd` are null with `session.why` `usage sweep busy and no earlier reading exists` (`cmdCost` area of cost.ts).
- The meter counts think and web-search tokens but prices only in, out, cache read and cache write 5m/1h (cost.ts `sumOf`). Pricing web search needs a new rate field. A price's optional `longContext` tier (0.29.0) prices a standard-speed row whose prompt (in + cache read + both cache writes) is over `abovePromptTokens` wholly at its rates (`ratesFor`, cost.ts).
- Not every Claude Code transcript has a `cost-state` line, so `claudeCodeEstimateUsd` can be null; pick a session that has one before a cross-check (ADR-0038 uses 7026b2da).

## Inbox transcript proof

`typedText` in `bin/inbox.ts` accepts a transcript line only when it is a main-thread user line (not `isSidechain`, `isMeta`, `isCompactSummary` or `isVisibleInTranscriptOnly`) with string content or text blocks and no `tool_result`. Either `origin.kind` is `human` and `promptSource` is `typed`, or the text is the `/truss:inbox` slash shape (`SLASH_SHAPE`) with `origin` absent or human and `promptSource` absent or typed. It refuses scheduled lines (`wakeupSource`, `scheduledTaskId` or `scheduledFireId` present, `turnOrigin` not `human`, `promptSource` not `typed`), so a `/loop` wakeup, a queued prompt and a `claude -p` prompt never count. It refuses every `OUTPUT_TAG` line (`bash-input`, `bash-stdout`, `bash-stderr`, `local-command-stdout`, `local-command-stderr`, `local-command-caveat`, `task-notification`), because task-notification returns carry the id and code and `argsOf` takes the first `<command-args>` anywhere in the text. `scanFile` also needs a string `uuid` and a `sessionId` equal to the session, and `chainOk` a `parentUuid` that resolves to an earlier row of the file (null only when no user or assistant row comes before it). `proof` needs a timestamp after the `open` op and arguments starting `<decision> <id> <code>`, where the code hashes to `codeHash`, then `raise <usd>` when the row has a raise, so a note's word cannot flip the decision. It also refuses a row without `raiseUsd` when the typed line carries `raise <usd>` (a typed raise is never dropped; `resolve` then names the missing `--raise-usd`), and a typed row whose `cwd` is an existing directory of another repo (`ownsCwd`: under the repo, or the same git common dir, passes). A row with no `cwd`, or one that no longer exists, passes (ADR-0037), so a replay from a deleted or moved repo is still accepted. `ownsCwd` depends on the transcript row's `cwd`, a Claude Code field that is not documented; a renamed or re-cloned repo can re-block resolved items.

The proof guards every read, not only `factory resolve`. `verifiedItems` is the one reading of the inbox, used by `blockingFor`, `budgetRaises`, the `escalate` dedupe, `resolve`, `mark-applied`, `factory inbox` and `longTermItems` in `bin/guard.ts`. A `by: client` row on a client kind counts only when its proof holds against the main transcript of the session it names; the first row that counts wins, and an unverified row is absent, with `reopened` in the listing. On `blocked`, `stall-unrecovered` and `pm-question` (`by: any` kinds; `KINDS` in `bin/inbox.ts`) a `by: pm` row counts without proof, and a `by: client` row is also run through the transcript proof (`needsProof` is true for every client row) but still counts when unproven; an unproven client note there only sets `noteUnbound`. A note that isn't the typed text is refused at `resolve`. A counted client resolve lists the proven typed text as its `note` in every reader of the fold, never the stored one; `noteUnbound` stays as a flag when the stored note differed. Rows from before 0.26 get the same proof; the ruling is in the ADR-0037 amendment.

Proof reads use `proofTranscriptRoot()` and `readProofFile` in `bin/transcripts.ts`: `.claude/projects` under `os.userInfo().homedir`, never an env var, so a non-default `CLAUDE_CONFIG_DIR` fails closed. `proofMain` in `bin/inbox.ts` walks that root. Tests stub those two seams with `tests/fixtures/inbox/proof-plugin.ts`, which replaces `bin/transcripts.ts` in a private plugin copy, because `TRUSS_TRANSCRIPTS_ROOT` no longer reaches the proof. `scanFile` caches one scan per file per process; the cost per process still grows with the transcripts the history names (ADR-0037 amendment). A process running as the same OS user can still write a passing line, and a deleted or rotated transcript makes the item block again. Change proof-check behaviour here and in `docs/features.md` together.

The same proof gates the plan approval (ADR-0045). `approvalProof` in `bin/inbox.ts` passes `factory approve --by client --item <E-id>` only for a verified, client-resolved `approve` of a `client-trigger` item of this truss dir (ref `run` only, not superseded, resolved by the client in this same session). It also refuses a resolve older than the plan: the resolve row's `ts` must be at or after the mtime of `plan.md`, else `plan.json`, so a proof given before a re-plan, or before `plan.json` existed, never approves the later plan. `confirmApproval` passes `approved = true` and skips only that check, since approving rewrote `plan.json`. `resolveItem` calls the approver `factory.ts` registers with `onPlanApprove` after a typed approve of a ref `run` item; a refusal rides in the output as `approveRefused`, and the spent item cannot approve (open a fresh item). The staleness check uses the row's `ts`, not the typed line's time, and `plan.md`'s mtime first; the replay cases are pinned in `tests/approve-029.check.ts`.

A human `/truss:x args` is probed as two lines with the same timestamp: a user line whose string content is `<command-message>x</command-message>\n<command-name>/truss:x</command-name>\n<command-args>ARGS</command-args>`, then an `isMeta: true`, `turnCompanion: true` user line holding the skill body, which ends `ARGUMENTS: ARGS`. The `isMeta` rule is what stops that second copy of the args from counting. Probed from a real session transcript (lines 114-115); the scrubbed sample is `plugins/truss/tests/fixtures/inbox/slash-command.jsonl`, with `__ID__`, `__CODE__` and `__TS__` placeholders.
